## 1. Update protocol (read before every contribution)

Every commit, pull request or agent session that changes anything in the repository, including documentation only, must update this file in the same change.

1. **Statuses.** Set the status of every task you touched. `[ ]` todo, `[~]` in progress, `[x]` done, `[!]` blocked (say by what), `[-]` dropped (say why).
2. **Evidence.** A task becomes `[x]` only after you ran its "Done when" check. Put the evidence in the task's `Evidence:` line (command and result, test file, or a link to `docs/spikes/Sx.md`). No evidence, no `[x]`.
3. **New work.** If the change does not match an existing task, add one in the right phase with an ID, priority, owner, estimate and a "Done when". Never leave unplanned work unrecorded.
4. **Discovered work.** Add tasks for follow-ups, bugs and new risks you found, even if you are not fixing them now.
5. **Requirement matrix.** Update the row in section 5 for any PRD requirement affected.
6. **Spikes and decisions.** Update section 6 when a spike moves. Append to section 8 when a design decision changes.
7. **Progress block.** Run `pnpm roadmap` to regenerate the block at the top. Never edit it by hand. CI fails if it is stale.
8. **Changelog.** Add one line to section 9 (newest first): date, author, task IDs, what changed, evidence.
9. **Dates.** Update "Last updated" and "Today's position".
10. **Honesty.** Do not mark work done that is not done. Do not delete a task to make progress look better; mark it `[-]` with a reason.

Until `A9` is done, step 7 is manual: recount and edit the block carefully, and say so in the changelog entry.

Task line format (the script parses it, so keep it exact):

```
- [ ] **C4** [P0] Short description. Reqs: GW-2. Deps: C1, C3. Owner: agent. Est: 3h.
  - Done when: concrete check.
  - Evidence: (filled in when done)
```

Owners: `agent`, `human` or `either`. Estimates are elapsed working hours with agent assistance and are guesses.

## 2. Definition of 100% ready

All of the following are true at once:

1. Every `[P0]` task is `[x]` with evidence.
2. Every P0 requirement in section 5 is done and covered by a passing test or a documented manual check.
3. `pnpm lint && pnpm typecheck && pnpm test && pnpm boundaries && pnpm roadmap:check` pass in CI on `main`.
4. A fresh clone runs `docker compose up` then `pnpm demo` with no keys and exits 0.
5. At least one real mainnet payment was routed through Intents with the result captured, or spike S1 or S7 formally recorded that it cannot be done, with the fallback documented.
6. The README states what is real, what is mocked and the known limitations.
7. The repository is public, contains no secrets and has a license.
8. The demo video and X post are published, the submission form is sent, and the confirmation is recorded in the changelog.
9. The docs match the built system. No open VERIFY marks remain that a spike could have closed.
